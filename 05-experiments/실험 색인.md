# 실험 색인

실험은 지식을 증거로 바꾸는 장치다. 환경·고정 변수·변경 변수·지표·반례가 없으면 성능 숫자만 기록하지 않는다.

## 우선 실험 후보

1. **Tomcat 포화** — 느린 endpoint와 제한된 worker에서 [[Tomcat 스레드 풀]] busy, queue, p99 변화를 측정한다.
2. **DB connection 경쟁** — worker와 connection 비율을 바꾸며 [[JDBC 커넥션 풀]] acquire time과 DB 처리량을 비교한다.
3. **transaction lock** — 두 transaction의 접근 순서를 바꿔 [[트랜잭션 락과 격리 수준]] wait와 deadlock을 재현한다.
4. **keyset 대 offset** — 데이터 크기별 rows examined와 latency로 [[키셋 페이징]] trade-off를 확인한다.
5. **idempotent retry** — 응답 직전 실패를 주입해 [[멱등성과 중복 처리]]가 side effect를 막는 범위를 검증한다.
6. **queue redelivery** — 처리 후 ack 전 consumer를 종료해 [[비동기 메시징과 전달 보장]]의 중복을 재현한다.
7. **cache failure** — Redis를 중단해 [[캐시와 Redis]] miss 폭증과 DB 보호 전략을 확인한다.

## 실행 순서

현재 질문과 직접 연결된 실험 하나만 [[실험 노트]]로 분리한다. 결과는 관련 개념의 level을 자동으로 올리지 않고, 사용자의 해석과 반례까지 확인한 뒤 근거로 사용한다.
