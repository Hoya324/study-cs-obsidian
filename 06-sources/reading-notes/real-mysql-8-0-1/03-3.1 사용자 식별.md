# 03-3.1 사용자 식별

## 읽은 위치

- 책: [[Real MySQL 8.0 1]]
- 범위: 03 사용자 및 권한 · 3.1 사용자 식별

## 내 메모 원문

> MySQL의 사용자는 다른 DBMS와 조금 달리 사용자 계정 뿐 아니라 사용자의 접속지점(IP주소)도 계정의 일부가 됨

## 핵심 정리

MySQL 계정은 사용자명 하나가 아니라 다음 조합으로 식별된다.

```text
'사용자명'@'접속 호스트'
```

예를 들어 `'app'@'localhost'`와 `'app'@'10.0.0.25'`는 사용자명이 같아도 서로 다른 계정이며, 별도의 인증 정보와 권한을 가질 수 있다.

접속 지점은 IP 주소만 뜻하지 않는다. literal IP, hostname, CIDR·netmask 같은 network 범위, `localhost`, `%` 같은 범위 표현이 올 수 있다. 계정에서 host 부분을 생략하면 `%`로 취급되므로 의도하지 않은 넓은 접속 범위가 되지 않는지 확인한다.

## 접속 시 계정 선택

```text
client의 사용자명·접속 위치
→ mysql.user의 User·Host 후보 탐색
→ 더 구체적인 Host가 앞선 순서에서 첫 일치 계정 선택
→ 그 계정의 인증 정보 확인
→ 연결 후 그 계정의 권한으로 요청 검사
```

중요한 점은 같은 사용자명의 권한을 합치는 것이 아니라 **가장 먼저 일치한 계정 하나**를 사용한다는 것이다. 예를 들어 구체적인 `'app'@'localhost'`가 있으면 넓은 `'app'@'%'`보다 먼저 일치할 수 있다.

## 로컬 연결과의 연결

Unix socket 같은 non-TCP 연결은 local connection으로 취급되어 `localhost` 계정과 연결된다. 따라서 `app@localhost`와 `app@%`의 비밀번호·권한이 다르면 `localhost` 또는 socket으로 접속할 때와 `127.0.0.1` TCP로 접속할 때 결과가 달라질 수 있다.

이 차이는 [[02-2.2.3 서버 연결 테스트]]의 `localhost → Unix domain socket`, `127.0.0.1 → TCP/IP` 구분과 이어진다.

## 문제를 확인하는 명령

```sql
SELECT USER(), CURRENT_USER();
SHOW GRANTS FOR CURRENT_USER();
```

- `USER()`: client가 제시한 사용자와 실제 접속 출발지를 보여 준다.
- `CURRENT_USER()`: 인증 과정에서 실제로 선택된 `'user'@'host'` 계정을 보여 준다.

접속은 되지만 예상한 권한이 없다면 `CURRENT_USER()`로 어떤 계정 row가 선택됐는지 먼저 확인한다.

## 보안상 기억할 점

- `%`는 편하지만 접속 범위가 가장 넓다. application subnet·host로 범위를 좁히는 편이 안전하다.
- 빈 사용자명은 anonymous account가 되며 예상한 named account보다 먼저 일치하는 상황을 만들 수 있다.
- 사용자명만 같다고 같은 계정이 아니다. 계정 생성·권한 확인·삭제 시 host 부분까지 명시한다.
- `skip_name_resolve`를 사용하면 hostname 기반 계정과 충돌하지 않는지 먼저 확인한다.

## 30초 회상

> MySQL 계정은 `'user'@'host'`다. 접속할 때 User와 Host가 맞는 후보 중 더 구체적인 Host가 우선하고, 첫 번째로 일치한 계정 하나의 인증 정보와 권한을 사용한다. 권한이 예상과 다르면 `USER()`가 아니라 `CURRENT_USER()`로 실제 선택 계정을 확인한다.
