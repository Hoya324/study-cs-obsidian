## 추가로 확인한 사실

- Handler status는 handler 요청 횟수이며 physical disk I/O byte가 아니다.
- current `realmysql` 8.0.44는 BACKGROUND 35, FOREGROUND 4였고, foreground 중 `one_connection`은 2개였다.
- `thread_cache_size`는 종료된 connection thread 재사용 cache이며 실행 동시성을 제어하는 thread pool이 아니다.
- default `thread_handling`은 `one-thread-per-connection`; 공식 Enterprise Thread Pool은 별도 상용 plugin이다.
- InnoDB는 buffer pool miss read I/O와 dirty page background flush를 구분한다.

## level 변경과 근거

아키텍처 level 0 → 2.

## 추가 캡처 · 4.1.2.2와 4.1.3

- 새 원문은 [[4.1 MySQL 엔진 아키텍쳐#사용자 정리 원문]]에 그대로 append했다.
- `IMG_7566.JPG`를 global memory와 session memory를 비교하는 4.1.3 절에 배치했다.
- OS의 `process 공유 heap + thread별 stack·session allocation` 관계를 Mermaid로 추가했다.
- `DAS`와 `SAN`, buffer의 일반 의미, redo log buffer와 binary log cache 차이에 답했다.
- `insert buffer`의 현재 명칭인 change buffer, 문맥상 `DCL → DML`, foreground logical read와 background read I/O의 차이를 별도 주의로 정리했다.
- 실제 `realmysql 8.0.44`에서 read·write I/O thread가 각각 4이고 buffer pool이 128 MiB인 것을 확인했다.
