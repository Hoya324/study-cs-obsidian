## 확인한 연결

- 설정을 기본 서버·연결, 문자셋·보안, 임시 memory, InnoDB, Performance Schema, TDE·password, binlog·replication, 운영 log로 분류했다.
- `max_connections=8000`과 `innodb_buffer_pool_size=20G`는 장비·pool·workload 전제 없이 복사할 수 없다.
- `innodb_flush_log_at_trx_commit=0`, `sync_binlog=0`, `innodb_doublewrite=OFF`는 서로 다른 durability 방어선을 동시에 약하게 한다.
- redo·undo·keyring·replication의 일부 option은 MySQL 8.0 후반에서 deprecated 또는 새 이름으로 전환됐다.
- 실제 `realmysql` 8.0.44는 128 MiB buffer pool, 151 connections, durability 중심 기본값을 사용한다.

## 미해결 연결

- 세 durability 설정이 각각 어떤 crash failure mode를 막는가?
- Hikari pool 합과 DB connection budget을 어떻게 계산하는가?
- Performance Schema의 관측 범위와 memory overhead를 어떻게 측정하는가?
- 책 예시와 현재 version 사이에서 제거된 option을 upgrade 전에 어떻게 자동 검사하는가?
