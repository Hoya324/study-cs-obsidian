## 공식 문서로 확인한 핵심

- 직접 `8.0 → 9.0`이 아니라 `8.0 → 8.4 LTS → 9.0 Innovation` 경로를 사용한다.
- 5.7에서 8.0으로 가는 출발점은 최초 GA인 5.7.9 이상이어야 하므로 5.7.8은 지원되지 않는다.
- 인플레이스는 기존 data directory에 새 서버를 시작하고, 논리적 방식은 구버전 SQL을 새 서버의 새 data directory에 적재한다.
- 각 단계에서 Upgrade Checker, backup·restore 검증, application test와 성능 비교가 필요하다.
- 9.0은 짧은 주기의 Innovation release이므로 현재 운영 target과 역사적 예시를 구분한다.

## level 변경과 근거

level 변경 없음. 중간 series와 GA 제약은 정확히 포착했지만, 두 방식의 내부 동작과 rollback 차이를 자신의 설명으로 확인하지 않았다.
