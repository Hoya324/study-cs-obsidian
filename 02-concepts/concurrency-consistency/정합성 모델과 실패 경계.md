# 정합성 모델과 실패 경계

## 한 문장 정의

정합성 모델은 여러 사본과 구성 요소가 어떤 순서·시점의 값을 보장하는지 설명하고 실패 경계는 원자적으로 묶이지 않는 구간을 드러낸다.

## 요청 흐름 속 위치

DB, Redis, queue와 외부 API 사이에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

version, replication lag, transaction/log, reconciliation work를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

부분 성공과 지연된 전파는 stale read, 이중 상태, 유실된 후속 작업을 만든다.

## 측정 지표와 확인 방법

lag, mismatch, pending age, reconciliation count, invariant violation를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

업무별 허용 불일치를 명시하고 상태 머신·outbox·보상·대사를 조합한다.
