# 운영체제 스케줄링과 컨텍스트 스위칭

## 한 문장 정의

운영체제 스케줄러는 실행 가능한 스레드에 CPU 시간을 배분하고 전환 시 레지스터와 실행 문맥을 교체한다.

## 요청 흐름 속 위치

동시에 runnable인 요청 처리 스레드들이 CPU를 경쟁하는 지점에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

CPU core, run queue, thread context, cache locality를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

실행 스레드가 코어보다 지나치게 많으면 전환 비용과 캐시 손실로 처리량이 정체될 수 있다.

## 측정 지표와 확인 방법

run queue, context switch/sec, CPU steal·system time, p99 latency를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

블로킹 작업과 CPU 작업을 구분하고 풀 크기·작업 단위를 조정하되 측정 없이 스레드를 늘리지 않는다.
