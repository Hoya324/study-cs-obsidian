# 프로세스와 스레드

## 한 문장 정의

프로세스는 독립 주소 공간과 자원을 가진 실행 단위이고, 스레드는 그 안에서 메모리를 공유하며 CPU 실행 흐름을 만든다.

## 요청 흐름 속 위치

JVM, MySQL, Redis 프로세스와 요청 처리 스레드가 실제 작업을 수행하는 구간에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

주소 공간, 스택, CPU 시간, 커널 스케줄러를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

스레드 과다 생성, 락 대기, 컨텍스트 스위칭 증가는 처리량 저하와 긴 꼬리 지연을 만든다.

## 측정 지표와 확인 방법

스레드 수와 상태, runnable·blocked 시간, context switch, CPU run queue를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

작업 특성과 제한 자원에 맞게 동시성을 제한하며 공유 상태와 블로킹 구간을 줄인다.
