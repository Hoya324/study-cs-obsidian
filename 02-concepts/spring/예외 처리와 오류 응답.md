# 예외 처리와 오류 응답

## 한 문장 정의

예외 처리는 내부 실패 원인을 보존하면서 외부 계약에 맞는 HTTP 상태와 안전한 메시지로 변환하는 경계다.

## 요청 흐름 속 위치

Spring 호출 계층에서 실패가 위로 전파되어 응답 또는 retry 판단으로 바뀌는 구간에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

stack trace, logging I/O, error serialization, retry traffic를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

모든 예외를 같은 상태로 숨기거나 내부 정보를 노출하면 복구 판단과 보안이 모두 나빠진다.

## 측정 지표와 확인 방법

exception type, error code, status, retryability, trace id를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

도메인·인프라 오류를 구분하고 안정된 error code, correlation id와 관측 가능한 cause chain을 유지한다.
