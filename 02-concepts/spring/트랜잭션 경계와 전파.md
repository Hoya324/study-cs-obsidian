# 트랜잭션 경계와 전파

## 한 문장 정의

Spring 트랜잭션 경계는 하나의 논리 작업이 사용할 DB connection과 commit·rollback 범위를 정하고 전파 옵션은 중첩 호출의 참여 방식을 정한다.

## 요청 흐름 속 위치

service 유스케이스가 여러 repository와 외부 호출을 조정하는 구간에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

DB connection, lock holding time, transaction log, thread-local context를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

너무 넓은 경계는 connection·lock을 오래 점유하고 잘못된 전파는 부분 commit이나 예상치 못한 rollback을 만든다.

## 측정 지표와 확인 방법

transaction duration, connection usage, lock wait, rollback count를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

DB 일관성 단위를 작고 명확하게 두고 외부 I/O와 상태 기록의 원자성 빈틈을 별도 패턴으로 다룬다.
