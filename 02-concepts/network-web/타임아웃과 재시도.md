# 타임아웃과 재시도

## 한 문장 정의

타임아웃은 기다림의 상한이고 재시도는 실패가 일시적이라는 가정 아래 작업을 다시 시도하는 정책이다.

## 요청 흐름 속 위치

연결, 읽기, DB 대기, 외부 호출과 메시지 처리의 모든 경계에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

대기 중인 thread·connection, retry traffic, deadline budget를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

상한 없는 대기는 풀 고갈을 만들고 무제한·동시 재시도는 장애 부하를 증폭한다.

## 측정 지표와 확인 방법

timeout count, retry count, success-after-retry, dependency latency, queue를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

전체 deadline을 하위 호출에 배분하고 지수 backoff·jitter·retry budget·멱등성을 함께 둔다.
