# 인덱스와 실행 계획

## 한 문장 정의

인덱스는 정렬된 보조 구조로 탐색 범위를 줄이고 실행 계획은 DB가 선택한 접근·조인·정렬 방법을 보여준다.

## 요청 흐름 속 위치

MySQL이 SQL을 파싱·최적화한 뒤 row를 읽는 구간에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

buffer pool, disk/page I/O, CPU comparison, index storage를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

선택도 낮은 인덱스, 잘못된 순서, 통계 오차는 많은 row 읽기와 임시 정렬을 만든다.

## 측정 지표와 확인 방법

rows examined/returned, access type, key, extra, query latency를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

실제 데이터 분포와 쿼리 형태로 계획을 확인하며 읽기 이득과 쓰기·공간 비용을 함께 본다.
