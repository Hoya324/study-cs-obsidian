# 키셋 페이징

## 한 문장 정의

키셋 페이징은 마지막 정렬 키 이후의 행을 조건으로 다음 페이지를 읽어 큰 offset 스캔과 변경 중 흔들림을 줄인다.

## 요청 흐름 속 위치

Batch reader와 대량 조회가 순서대로 row를 가져오는 구간에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

index page, DB CPU/I/O, cursor state를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

정렬 키가 유일·불변이 아니면 누락·중복이 생기고 부적합한 index면 범위 스캔이 커진다.

## 측정 지표와 확인 방법

rows examined, query latency by page, duplicate/missing count를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

유일한 복합 정렬 키와 일치하는 index를 쓰고 snapshot 요구와 동시 변경 의미를 정한다.
