# 컨테이너와 이미지

## 한 문장 정의

컨테이너는 운영체제 격리 기능으로 프로세스를 실행하고 이미지는 그 파일 시스템과 실행 설정을 재현 가능하게 묶는다.

## 요청 흐름 속 위치

JVM 애플리케이션을 배포 가능한 단위로 패키징하고 실행하는 구간에 놓인다.

## 왜 필요한가

이 개념을 알아야 요청의 계산 시간과 대기 시간을 구분하고, 실패가 어느 경계에서 시작됐는지 설명할 수 있다.

## 내부 동작

현재는 큰 틀을 잡는 시드다. 다음 진단에서 자신의 말로 흐름을 설명한 뒤 내부 구조와 반례를 채운다.

## 소비하는 리소스

CPU/memory limit, filesystem layer, network namespace, image storage를 사용하거나 점유한다.

## 실패 조건과 관찰되는 증상

limit 오설정, mutable image, root 실행과 상태 저장 오해는 OOM·재현 실패·보안 문제를 만든다.

## 측정 지표와 확인 방법

container CPU/memory, restart/OOMKilled, image digest, startup time를 요청 지연 및 오류와 같은 시간축에서 확인한다.

## 해결 전략과 트레이드오프

불변 image·비root·명시적 limit과 외부화된 상태를 사용하고 같은 digest를 환경 간 이동한다.
